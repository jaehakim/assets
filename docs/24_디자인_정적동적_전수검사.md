## 1. 검사 방법

| 구분 | 방법 |
|---|---|
| **정적검사** | 소스(`src.jsx`, `styles/*.css`, `nginx.conf`) 분석 — 토큰 준수(색·글자·모서리·여백), `!important`, 화면 폭 기준점·z-index·그림자 종류, 미사용 CSS(전 화면·상태를 실제로 띄워 선택자 일치 여부 측정), 문구 언어 혼용, 브라우저 기본 대화상자 사용, 마크업 접근성 패턴 |
| **동적검사** | 운영 화면을 실제 브라우저로 실행(관리자 세션, 읽기 전용) — axe-core 4.10 자동 접근성 검사(WCAG 2.0~2.2 AA + 모범 사례), 해상도 1920·1440·1280·1024·768·390·360px와 200% 확대(720×450), 키보드 탐색·포커스 표시·모달 포커스 가둠·Esc, 성능(LCP·CLS·전송량), 콘솔 오류 |

## 3. 조치 (Frontend 0.6.0)

## 4. 남은 과제 (권장 순서)

| 순위 | 과제 | 이유 |
|---|---|---|
| 1 | 브라우저 기본 `confirm/prompt` 6곳 → 앱 대화상자 컴포넌트 | 디자인 일관성, 차단 사유 입력의 모바일 사용성, 위험 동작 강조 |
| 2 | mermaid를 시스템 가이드 진입 시에만 로드(코드 분할) | 첫 화면 JS 약 −40% 예상 |
| 3 | 화면 폭 기준점 10종 → 3종(1100·900·650), z-index 11종 → 계층 토큰 5단계, 그림자 26종 → 3단계 | 반응형 동작 예측성, 겹침 사고 방지 |
| 4 | 단계 밖 여백 180곳을 `--space-*`로 | 여백 리듬 통일 |
| 5 | `!important` 201개 단계적 제거 | 통합으로 순서가 고정됐으므로 제거마다 픽셀 비교로 검증 가능 |
| 6 | 미사용 선택자 156개 재확인 | 오류·로딩 상태를 띄운 커버리지로 재측정 후 정리 |
